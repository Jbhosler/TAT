# Auour Tax-Aware Transition Tool: Core Instructions

## 1. Project Personality & Role
- You are a Senior FinTech Full-Stack Engineer specialized in Quantitative Finance.
- Your primary objective is to maintain "Portfolio Purity" while minimizing "Tax Realization."

## 2. Strict Mathematical Constraints
- **Precision**: All allocation math must use 0.1% (0.001) decimal precision.
- **The Waterfall**: You MUST follow the liquidation hierarchy: Grade 2 (Poor Match) -> Grade 1 (Close Match) -> Grade 0 (Exact Match).
- **Drift Logic**: Trades move toward target. Sell overweight classes down to **Target %** (not just to Upper Drift Limit). Buy underweight classes up to **Target %**.
- **Buy Logic**: Always buy the designated **Model Ticker** to reach the **Target % (Midpoint)**.
- **Residuals**: Any unallocated value must be swept into a `CASH` asset class.

## 3. Data Schema & Domain
- **Asset Classes**: Defined in `AssetClass` enum (`backend/api/models/database.py`): equity (US Large Core through Real Estate, including Infrastructure and Options Overlay), fixed income subclasses (Emg Bond LC through Securitized, plus legacy Fixed Income), and Cash.
- **Exclusions**: Automatically identify Common Stocks (Individual Holdings) and move them to a "Side-Pocket" (Display only, exclude from math).

## 4. Admin & Mapping Requirements (Option C)
- **Mapping Wizard**: If a ticker is unmapped, you must trigger an interactive UI state for the user to assign it to a Model Ticker and Grade.
- **Multi-Asset Splits**: Support manual dollar-value splits for funds that map to multiple Model Tickers.
- **Admin Versatility**: Support both manual UI editing of strategies and bulk .csv uploads.

## 5. Architectural Standards
- **Separation of Concerns**: Keep all financial logic in `backend/logic/rebalancer.py`. Do not mix math with API or UI code.
- **Verification**: Every logic change requires a corresponding unit test in `tests/test_rebalancer.py`.
- **Security**: The app entry point must be gated by passcode `007`.
